## Culture Fit / Behavioral Interview

Build STAR outlines around actual final-CV experiences, with a clear distinction between independent decisions and collaboration. Likely questions include:

- How did you turn an ambiguous integration need into a usable service? Use the vendor-neutral gateway and its business-demo result; explain how contracts and adapters bounded the work.
- Describe a security-sensitive decision you owned. Use the telephony backend, protection of customer phone data, formal review and production delivery. Do not imply financial custody or a legal certification.
- Tell us about simplifying a running backend system. Use consolidation of data-processing pipelines and removal of full-history reads without downtime.
- How did you work with product and infrastructure colleagues when requirements crossed team boundaries? Select a real incident from supported collaboration; the sources establish roles, not a scripted disagreement.
- Explain a performance improvement with imperfect information. Use the airSlate DB or API example, distinguish lead contribution from implementation by others, and identify what Prometheus established.
- Describe how you improved delivery without sacrificing stability. Use the airSlate CI/CD work that shortened cycles and improved consistency.
- What would you do when an unfamiliar language or financial concept blocks progress? Describe an actual learning approach, a small validation experiment and appropriate review; do not invent a prior Rust project.

Use only defensible figures and distinguish personal from team contribution.

## Technical Interview

High Priority — Go service and API design. Practice request validation, authentication boundaries, idempotency, cancellation, timeouts, retries and structured error handling. Explain how asynchronous work is correlated to an API request and how duplicate requests are handled. The gateway is a useful real example of service integration, but financial transaction semantics require separate reasoning rather than claiming the same production domain.

High Priority — off-chain/on-chain state. Study transaction submission, confirmations, finality, reorgs, nonce handling, settlement status and reconciliation. Design an API that remains correct when a chain or external provider is unavailable. Discuss which component is authoritative and how pending, failed and finalized states are exposed. Treat these as system-design preparation, not a claim that the candidate built Native's architecture or operated a DEX.

High Priority — financial correctness and security. Review decimal precision, rounding, replay protection, signature verification boundaries and separation of secrets from application data. Explain why floating-point shortcuts can be unsafe for values requiring exact representation. Ask whether the backend signs transactions, only routes intent or integrates with a separate execution service before choosing a design.

High Priority — databases and production performance. PostgreSQL and MySQL are supported candidate skills. Practice index selection, query plans, transactions, isolation, locks and compatible migrations. Redis is unconfirmed: study cache invalidation, eviction, expiration and durable-store boundaries. Prepare a migration rollout/rollback discussion without inventing a past migration achievement. Use the real airSlate workload and API examples to explain measurement and consequences.

High Priority — delivery and incident handling. Discuss CI/CD quality gates, compatibility, staged rollout, rollback and operational visibility. GitHub Actions is supported; Bitbucket is not established. Explain the recorded release-cycle and consistency improvements without restoring the withdrawn ECS migration. Review metrics, logs and tracing as different tools and how they support an incident timeline.

Medium Priority — Rust ownership, borrowing, errors and async execution; study supports a ramp-up discussion, not production expertise. Review trading vocabulary, including spreads, slippage and execution risk. Low Priority — smart-contract implementation unless the interview explicitly requires it.

## Preparation Plan

Must prepare before screening: a concise backend introduction, language-gap disclosure, current availability and Italy-contract questions. Before technical: a Go API exercise, an asynchronous transaction-state design, a relational query investigation, a safe-delivery example and foundational Rust study. Before the final discussion: a measured explanation of the domain transition, a real collaboration story and questions about ownership and on-call. Rehearse each story aloud with contribution, scope, observed result and limitations clearly separated.
