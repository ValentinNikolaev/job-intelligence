## Culture Fit / Behavioral Interview

Prepare seven questions using real work, with notes rather than fabricated scripts.

1. When did you define a boundary that other engineers could use? Use the helpdesk gateway, vendor-specific adapters and explicit contracts. Explain the delivered business demo and distinguish that milestone from broader adoption.
2. How did you handle a security decision with several stakeholders? Use telephony architecture, security review and collaboration with frontend and SRE. Explain what you decided and what required approval.
3. When did you simplify a system without interrupting users? Use Snowflake pipeline consolidation and the documented absence of downtime. Avoid code-size figures as the main value.
4. How did you balance delivery with technical debt? Use airSlate release responsibilities, with a concrete remembered decision. The source establishes responsibility, not a particular conflict narrative.
5. How did you lead without claiming all implementation? Use airSlate API and feature-delivery work, attributing team results to backend leadership.
6. How did you evolve a contract while consumers depended on it? Use CRURATED parallel event-version publication. Explain the actual production arrangement rather than inventing migration counts.
7. What did you learn when moving a product beyond prototype? Use Hyprr's closed-beta milestone and work with the CTO. Clarify the personal contribution and known limits of the result.

For each story, prepare situation, responsibility, action and outcome. Separate what you remember from what the evidence explicitly records. Do not add invented incidents, disagreements or lessons merely to fill STAR slots.

## Technical Interview

High Priority: Go service design. Rehearse context cancellation, goroutine lifecycle, race prevention, bounded concurrency, error propagation and HTTP handlers. Connect these to an API integration without presenting generic knowledge as work already performed.

High Priority: shared SaaS APIs and identity boundaries. Design tenant-scoped ingestion, authentication versus authorization, idempotency, contract changes, permission checks and audit trails. Explain where tenant identity is established and how it reaches storage and queues. The gateway and telephony are the strongest practical anchors.

High Priority: production reliability and public cloud. Discuss SQS delivery semantics, duplicate processing, backpressure, timeouts, retry budgets, observability and safe rollout. Know which choices were yours and which belonged to SRE. Treat incident response as a technical discussion, not permission to invent an outage story.

High Priority: relational data and performance. Review indexes, transactions, query plans, connection limits, locks and database workload redistribution. Use airSlate's stability result and be precise about the difference between reduced load and an absolute utilization ceiling.

High Priority: Python expectations. If the team accepts the profile, agree on what a fair language exercise should test. Review syntax and concurrency models for preparation while preserving the distinction between study and professional experience.

Medium Priority: cloud differences, centralized configuration, licensing orchestration and multi-product provisioning. These are role-relevant topics with transferable evidence, not delivered candidate projects. Medium Priority: coding exercises on parsing, collections, dependency boundaries and tests. Low Priority: frontend framework trivia unless the interviewer confirms frontend work is substantial. Do not claim Angular, React or Java/Spring experience.
