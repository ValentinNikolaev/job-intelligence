## Culture Fit / Behavioral Interview

Use real examples and separate your own decisions from team contributions. Structure each answer around the problem, your role, decision, outcome and what remains uncertain. Prepare these questions:

1. Tell me about a technical decision you owned end to end. Use the Simple.life calling platform and distinguish backend ownership from frontend and SRE contributions.
2. Describe a time you worked across functions. Discuss the calling platform's security sign-off and cross-functional delivery without claiming to have led every participant.
3. How did you balance reliability and delivery speed? Explain the design and fallback choices in a system you actually worked on; do not invent a tradeoff.
4. Tell me about a system that became easier to maintain. Use the Snowflake-to-Intercom consolidation and explain why shared structure mattered.
5. How have you handled an ambiguous requirement? Choose a real example and describe what was clarified, avoiding invented conversations.
6. Describe mentoring or technical leadership. Use the confirmed airSlate or Hyprr scope and distinguish coaching duties from outcomes that were not measured.
7. Tell me about a disagreement on architecture. Select an actual event if available; if none is ready, say so rather than inventing one.
8. How do you work independently with stakeholders? Use a specific documented decision and explain when you involved others.

Verify each story’s dates, contribution, delivery status and figures.

## Technical Interview

**High priority — PHP and Laravel:** Review the version-specific changes relevant to PHP 8, dependency injection, service boundaries, error handling and tests. Prepare a real Laravel example and make clear which PHP versions you actually used. Explain the Laravel/Symfony logger's purpose and existing interservice standard without claiming an unrecorded adoption or architecture outcome.

**High priority — architecture and APIs:** Explain the helpdesk gateway's vendor-neutral model, OpenAPI contracts, adapters, webhook ingestion and per-tenant separation. Discuss idempotency, failure handling and versioning as design questions, distinguishing actual choices from alternatives you would consider today. Prepare the CRURATED event schema and analytics pipeline as a second, separate example.

**High priority — databases and performance:** Walk through the airSlate database bottleneck and what the team measured, the change made and how stability was assessed. Be precise that the API performance result involved a backend team and Prometheus; do not assert sole attribution or invent a query plan. Rehearse indexing and query plans using clearly labelled hypotheticals.

**High priority — testing and code quality:** Explain the tests around consolidated pipelines, which workflows were covered and what failures the tests could catch. Review integration boundaries, mocks versus real dependencies and code-review decisions. Do not claim a framework that the evidence does not establish.

**High priority — Node.js, Vue.js and AI coding tools:** These are explicit role requirements but the supplied evidence does not confirm practical use. Establish your actual experience and be ready to describe its scope honestly. Building LLM support functionality is not evidence of using an AI coding assistant. Review relevant concepts, but distinguish study from production delivery.

**Medium priority — Symfony:** Explain actual use of the framework and what is known about its architecture; identify which versions you actually used and which features you would refresh. Review services and integration tests.

**Medium priority — AWS and containers:** Explain Amazon Connect, IAM federation and the production platform's privacy and calling controls. Confirm any hands-on Docker experience separately. Do not attribute the unconfirmed ECS migration to airSlate.

**Medium priority — coding and design:** Practise implementing a small API integration, handling retries safely and reasoning about complexity. State assumptions and test edge cases.

## Preparation Plan

**Must prepare:** verify PHP versions and years; establish the real level of Node, Vue, Docker and AI coding-tool use; confirm the contractor route and availability. Select the calling platform and analytics system as grounded stories.
