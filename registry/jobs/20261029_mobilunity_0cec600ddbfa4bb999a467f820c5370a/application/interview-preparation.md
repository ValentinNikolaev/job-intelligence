## Technical Interview

**High Priority — PHP and Laravel.** Review service boundaries, dependency injection, request validation, queues, retries, transaction boundaries and practical testing. Be ready to read unfamiliar Laravel code and explain a minimal, maintainable change. Use real code experience when describing past delivery. Practice examples can demonstrate reasoning without becoming historical claims.

**High Priority — SQL and database performance.** Practise reading an execution plan, choosing an index, identifying unnecessary queries and reasoning about locks and transaction isolation. For airSlate, explain the original bottleneck, workload redistribution, monitoring and personal backend-lead contribution. Do not invent the exact query or index. The CV states a qualitative result, so explain what evidence supported it before introducing figures.

**High Priority — API and system design.** Work through a booking service with concurrent reservation requests, idempotency, capacity limits and cancellation. This is a practice scenario, not a description of the client's architecture. Discuss where consistency is essential, how events reach other services, how contracts evolve and what happens when a downstream system is unavailable. Connect trade-offs to failure consequences and maintenance costs.

**High Priority — Production diagnosis.** Explain how logs and metrics guide investigation. Prepare rollback reasoning from work you owned. Distinguish restored operation from an architectural improvement.

**Medium Priority — Frontend and identity.** Refresh enough TypeScript and React to discuss component boundaries, asynchronous state and API errors honestly. Ask about expected depth. Treat Keycloak and state libraries as learning topics, not established experience. Review OAuth and OIDC concepts without claiming a Keycloak implementation.

**Medium Priority — AWS and delivery.** Revisit queues, access boundaries, containers and CI/CD. **Low Priority — restaurant-specific platform knowledge.** Understand the vocabulary without guessing the vendor's design.
