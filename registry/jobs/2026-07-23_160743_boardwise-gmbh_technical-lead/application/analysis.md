# Application Analysis

## Vacancy Summary

Boardwise is hiring a remote-first Technical Lead for a hands-on engineering leadership role. The role combines people leadership, delivery ownership, architectural direction, cross-team collaboration, and daily AI-assisted engineering.

Explicit requirements:

- Lead and coach engineers through 1:1s, feedback, hiring, onboarding, and professional growth.
- Translate product goals into engineering plans, break complex initiatives into work packages, scope, estimate, prioritize, and balance technical debt with delivery.
- Drive architectural decisions, reviews, mentoring, performance, reliability, maintainability, features, refactoring, and production issue resolution.
- Collaborate with Technical Leads and Product Managers and coordinate dependencies across teams.
- Use AI daily for implementation, code reviews, testing, debugging, documentation, and architecture; coach the team in AI adoption.
- 5+ years of backend or full-stack development.
- Strong ASP.NET Core experience.
- React, TypeScript, and JavaScript experience.
- Scalable SaaS and cloud-native architecture experience.
- F# or strong C# skills with motivation to learn functional programming.

Preferred or nice-to-have requirements:

- Azure and Microsoft 365 APIs.
- Domain-Driven Design, CQRS, Event Sourcing, Vertical Slice Architecture.
- Microsoft Graph API, React Native, enterprise B2B software, governance, or regulated industries.

Reasonable inferences:

- Hiring managers will screen strongly for Microsoft ecosystem depth because Boardwise's public product positioning emphasizes Microsoft 365 integration.
- The role needs a hands-on leader who can set direction while still contributing code and production fixes.
- The AI-first wording suggests practical AI workflow fluency matters more than generic interest in AI.

Candidate fit:

- Strong fit for technical leadership, coaching, hiring, planning, pragmatic delivery, SaaS reliability, production ownership, AI-assisted automation, and backend architecture.
- Partial fit for cloud-native architecture through AWS and Kubernetes rather than Azure.
- Material gap for ASP.NET Core, C#, F#, React, TypeScript, Azure, Microsoft 365 APIs, and Microsoft Graph API.

Material weaknesses:

- No supported React, TypeScript, JavaScript, Azure, Microsoft 365 APIs, or Microsoft Graph API evidence. This matters for both ATS and technical screening. Safe rewrite: emphasize backend and cloud-native experience while noting AWS/Kubernetes instead of Azure.
- Leadership dates are somewhat fragmented across LinkedIn and CV sources. This matters because recruiters may need clear chronology. Safe rewrite: split airSlate into Technical Lead and Senior Software Developer sections while preserving source dates.

Applied changes:

- Added Technical Lead headline and summary.
- Restored airSlate Technical Lead, Hyprr Technical Lead, and PDFfiller leadership evidence.
- Kept skills limited to supported evidence.
- Added a candid cover-letter paragraph about the Microsoft stack ramp-up.

## Red Flags

- Stack mismatch: the largest red flag is absence of Microsoft/.NET/F#/React/Azure evidence. Safe handling is to acknowledge it transparently and position the candidate as a strong technical leader with adjacent backend, SaaS, cloud, and AI workflow experience.
- Chronology conflict: candidate sources list Simple.life/Simple App dates differently, including "Present" in LinkedIn and March 2026 in the backend CV. The CV uses the backend CV's March 2026 endpoint while the analysis preserves the uncertainty by not claiming current employment.
- English proficiency conflict: source evidence contains duplicate and conflicting English levels. The tailored CV uses "upper-intermediate / professional working proficiency" to avoid overstating fluency.
- Unsupported buzzwords: DDD, CQRS, Event Sourcing, Vertical Slice Architecture, Microsoft Graph API, ASP.NET Core, C#, F#, React, TypeScript, and Azure were not added as candidate skills because source evidence does not support them.
- Job hopping risk: recent Simple.life and CRURATED overlap or chronology conflict in source evidence was avoided by using the backend CV chronology and not adding CRURATED to the final CV, because the Technical Lead role benefits more from clearer leadership evidence.
