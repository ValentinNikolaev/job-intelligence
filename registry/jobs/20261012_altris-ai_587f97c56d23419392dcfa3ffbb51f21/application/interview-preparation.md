## Technical Interview

**High Priority:** PHP, Laravel/Symfony, SQL/MySQL/PostgreSQL, API design, modular code, CI/CD, integration boundaries and production reliability. **High Priority:** testing strategy, MongoDB/Redis and Docker, because the posting explicitly requires them. Prepare real evidence where available and state unknowns plainly; PHPUnit is a named example of a test framework. **Medium Priority:** AWS and direct UI contribution. **Low Priority:** unrelated imaging-model implementation, which is not a stated PHP responsibility.

Expect a design exercise for a PHP service receiving clinical-workflow data: explain contracts, validation, relational modelling, error handling, privacy boundaries, auditability, tests and deployment. Avoid claiming compliance expertise; use the example to show engineering judgment. Be ready to explain how an event schema evolves and how a data pipeline is observed.

Use STAR answers with a bounded factual result. For CRURATED, state the production PHP analytics scope, the candidate’s technical ownership, and the measured throughput, onboarding or reliability result; do not turn them into a company-wide claim. For Simple.life, explain the design-to-security-review-to-release path with frontend/SRE collaboration. For airSlate, make leadership contribution clear. System-design study should cover data contracts, schema migration, relational storage, test layers, observability and a staged deployment. Prepare Docker/NoSQL/PHPUnit as direct questions: say the CV does not claim them and ask about the actual stack rather than guessing.

Practise a bounded Laravel module-extension exercise: define the request and response, choose transaction boundaries, explain database constraints, and describe unit versus integration tests. Discuss a failed external-service call, safe retry behaviour and release verification. Present this as a design exercise, not as a claim of hands-on experience with an unverified framework or infrastructure tool.
