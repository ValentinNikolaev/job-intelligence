# Application analysis — Kindgeek

## Vacancy Summary

Kindgeek seeks a PHP Developer with Symfony for a long-term partner’s banking product. The engineer would develop backend services for onboarding and client-data maintenance, document inherited code, discuss architecture and non-functional requirements with product and technology leaders, and support frontend engineers. The initial full-time engagement is three to four months. Registry source: https://jobs.dou.ua/companies/kindgeek/vacancies/381104/. Direct application: https://kindgeeks.breezy.hr/p/1e78cf279762-php-developer-symfony/apply?state=published.

The description embedded in the live Breezy form specifies 3–4+ years building scalable systems, PHP, at least two commercial Symfony projects, SQL including MariaDB, architecture and integrations, React and NextJS, Python with FastAPI and Django, testing, communication and B2 English. The frontend and Python requirements remain present in the live description. The archived DOU capture specified 5+ years. An efficient handover is an inferred priority because the assignment is short and explicitly includes knowledge transition.

## Company Research

**Fact:** Kindgeek describes itself as a fintech software development company offering product engineering and dedicated teams, along with technical audits and architecture reviews: https://www.kindgeek.com/.

**Inference:** Experience explaining existing backend systems and integrating services may be useful in an embedded assignment where code ownership is being transferred. The posting itself supplies the knowledge-transition context.

**Unknown:** The end client, current architecture, Symfony version, deployment practices, extension prospects and contracting arrangements from Italy are not established. The direct form labels the role fully remote with no location restrictions, although contract arrangements still need confirmation.

## Initial Resume Audit

The baseline candidate CV demonstrates substantial production backend and operations experience. The strongest directly relevant PHP/Symfony evidence is a shared Laravel/Symfony logging package at airSlate, while CRURATED establishes PHP-oriented work and production integration ownership. The simple presence of a framework on a skills list does not establish the employer's requested two commercial Symfony projects. Sources also support MySQL and PostgreSQL, but do not explicitly name MariaDB. React, NextJS, Python frameworks and the named repository platforms remain unconfirmed.

The baseline gives strong space to Go support automation. That experience remains useful for integrations and maintaining production services, but the application should make PHP, Symfony and knowledge sharing easier to find. Candidate-confirmed dates and overlap also matter: CRURATED was a concurrent part-time subcontract alongside Simple.life. The CV marks the overlap and retains older permitted roles as dated entries.

## Strict Hiring Manager Review

The architecture and delivery evidence is concrete: at CRURATED the candidate owned production event analytics and an external integration, and at airSlate reduced database peak load and worked from epic decomposition to delivery. The logger is a direct Symfony example, but its impact and adoption are not established. It should be discussed as a delivered package aligned with a standard, without an invented organisation-wide result.

The main challenge is not generic seniority. The employer explicitly wants two Symfony projects and knowledge of frontend and Python frameworks. Current sources do not confirm either the project count or the latter technologies. Ask for project names, responsibilities and versions, and clarify the expected depth in each secondary stack. Do not claim an absence of experience based on an incomplete record.

## Red Flags

1. **Symfony project count:** unknown against an explicit requirement. Obtain two verifiable project examples or disclose the limit accurately.
2. **React, NextJS and Python frameworks:** practical exposure is unknown. Ask how much of the role involves reviewing or changing those codebases.
3. **Location and duration:** the direct form states fully remote without location restrictions, while contracting arrangements and an initial three-to-four-month commitment remain to be confirmed. Ask about extension expectations.
4. **MariaDB and repository platforms:** analogous SQL and delivery experience is supported, but the named tools are not. Check direct exposure before representing them as skills.

Resolve the commercial Symfony project count, secondary-stack expectations, contract arrangements and duration before making stronger fit claims or completing the application.
