## Culture Fit / Behavioral Interview

Prepare the following seven questions using real events. Use STAR to organise facts, keeping your own decisions separate from the team's contribution. Unknown results stay unknown.

1. When did you own an ambiguous problem before implementation? Use the telephony epic and design document, then identify the security decisions you actually made.
2. How did you work across disciplines? Use telephony delivery with frontend and SRE. Describe the boundary between your backend responsibility and theirs.
3. When did you choose a reusable design? Use the vendor-neutral helpdesk gateway, its contracts and the B2B demonstration it enabled.
4. How did you evolve a running integration? Use CRURATED's parallel event-version publication. Explain the consumers and compatibility constraints you can substantiate.
5. How did you improve production reliability? Use airSlate's database workload work and service stability during traffic peaks. Attribute the result to backend leadership.
6. When did you reduce repeated work? Use the Snowflake-to-Intercom consolidation and eliminated historical reads, avoiding code-size or test-count arguments.
7. How did you balance delivery and technical debt? Use airSlate's release planning and backend delivery responsibilities. Choose one actual trade-off before the interview rather than inventing a neat story.

For each, rehearse the problem, your authority, actual alternatives, delivery stage and known consequence. Explain limitations plainly.

## Technical Interview

**High Priority — Go and service design.** Revisit concurrency, cancellation, timeouts, error handling, idempotency and testable boundaries. Practise implementing a small webhook handler or bounded worker pool. Explain behaviour when a dependency times out or a message is delivered twice. These are practice exercises, not claims about a particular past implementation.

**High Priority — public API evolution.** This is the largest technical evidence gap. Prepare resource models, additive versus breaking changes, version negotiation, deprecation, consumer telemetry and migration windows. Use the gateway's OpenAPI contracts as real experience, then distinguish hypothetical public API policy from actual delivery. Parallel event versions are relevant but do not prove an external compatibility commitment.

**High Priority — shared authentication and tenant boundaries.** Discuss authentication versus authorisation, identity mapping, permission checks, audit records and safe credential handling. Ground past experience in Crutrade authentication/OTP and telephony privacy decisions. Do not imply ownership of a company-wide identity platform.

**High Priority — resilient notifications.** Design a notification service with delivery state, retries, deduplication, backpressure and operational signals. Ask about delivery guarantees before proposing a solution.

**Medium Priority — databases and infrastructure.** Review query plans, indexing, transaction boundaries, queue/DB consistency, Kubernetes deployment basics and observable failure modes. Use airSlate's workload redistribution to explain a real operating consequence. Do not use the withdrawn ECS migration. General Kubernetes knowledge and a claimed migration are different evidence.

**Medium Priority — coding and data modelling.** Practise a small API, pagination and concurrent processing exercise, with readable tests and explicit failure handling. **Low Priority — specialist supply-chain internals.** Learn the purpose of hardened artifacts, provenance and SBOMs, but do not present them as past ownership. The role is customer platform engineering rather than a stated cryptography specialist position.
