## Technical Interview

High Priority — product-data modelling. Practise a hypothetical model for products, variants, manufacturer identifiers, specifications, units, prices and configurable options. Label it as a proposed design, not past PIM experience. Explain how source values differ from normalised values and how you would preserve provenance. Ask which identifiers are authoritative before proposing deduplication rules. Avoid assuming that identical descriptions mean identical products.

High Priority — ingestion correctness. Design imports that can resume after interruption, handle retries safely and distinguish a rejected record from a failed job. Explain initial imports versus incremental updates and how corrections move through the system. Use your real pipeline and versioned-event experience to explain transferable judgment. Do not claim a successfully completed million-product migration or invent a production volume.

High Priority — PHP and Symfony. Review the actual framework components you know, dependency boundaries, validation, controllers, services, background processing and automated tests. Be ready for hands-on coding. State any gap in Symfony Messenger, Doctrine or the required PHP version directly.

High Priority — data storage and reliability. Review PostgreSQL indexing, query plans, uniqueness, transactions and schema evolution. Discuss the limits of caching and when stale price or quote data becomes unacceptable. Redis is named in the vacancy, but professional delivery with it is not established. Treat cache design as interview reasoning and ask which consistency guarantees matter to users.

High Priority — crawling and scraping. Learn the reliability questions behind source changes, access policies, throttling, parser drift and evidence capture. Do not present these study topics as experience. Be candid about whether you have a real delivered crawler example outside the supplied record. If not, explain how you would validate a small source-specific implementation before promising broad coverage.

Medium Priority — quoting and frontend. Work through line items, markup, discounts, quote revisions and the relationship between catalogue changes and an already issued quote. Ask about the exact business rules before designing them. React is preferred, while interfaces are part of the role. Clarify what you can deliver yourself and what requires collaboration instead of using full-stack as a vague claim.

Medium Priority — monitoring and deployment. Discuss operational metrics for job backlog, failures, data freshness and review queues as a proposed design. Ground your production experience in real monitoring, release pipelines and service operations. Do not use the withdrawn airSlate ECS-to-Kubernetes migration. Low Priority — kitchen-equipment expertise until a domain expert explains the main product and configuration rules.
