## Culture Fit / Behavioral Interview

Prepare short STAR outlines for these real CV anchors. Supply only actual situations, personal contributions and outcomes; the questions are rehearsal prompts, not invented candidate answers.

1. How did you work independently on a bounded assignment? Use CRURATED's confirmed part-time consulting and production integration ownership. Explain scope and coordination without claiming line management.
2. How did a design make new functionality easier to add? Use modular analytics-stream delivery and its confirmed setup-time improvement.
3. Describe collaboration across technical disciplines. Use Simple.life's calling platform and work with frontend/SRE colleagues. Distinguish backend responsibility from their contributions.
4. When did operational evidence influence your work? Use airSlate's API optimization and Prometheus results. Explain what the measurements establish and what remains unknown.
5. How did you simplify existing application processing safely? Use the common Snowflake-to-Intercom engine and unchanged public interfaces. Do not invent rollout mechanics.
6. How would you handle an assignment requiring an unfamiliar skill? Explain the current frontend evidence boundary, then outline a transparent learning and escalation approach as a hypothetical response.

## Technical Interview

**High Priority — Laravel/PHP coding:** rehearse a small API endpoint with validation, authorization boundaries, database access, error handling and tests. Discuss readable structure and how to communicate assumptions before implementation. Use supported Laravel work; do not invent particular framework versions, packages or years of tool use.

**High Priority — frontend scope:** clarify React assessment expectations first. Review component state, form handling, asynchronous requests and basic CSS as study topics. A learning exercise is not production evidence. If asked for a React project, state that none is substantiated in the supplied materials rather than presenting the backend gateway as a full-stack project.

**High Priority — databases:** practice MySQL schema design, indexes, query inspection, transactions and duplicate-request handling. Connect performance discussion to airSlate's supported database stability work. Do not transfer a MySQL achievement to PostgreSQL or invent a measured latency result.

**Medium Priority — architecture and integration:** sketch a Laravel application consuming an external service, with explicit failure states, background processing and observable results. CRURATED's event integration and customer-account functions provide factual discussion anchors; proposed designs must remain hypothetical.

**Medium Priority — infrastructure and delivery:** discuss supported CI/CD, AWS and monitoring experience, including safe releases and debugging. Git appears in the requirements, while GitHub Actions alone does not prove the requested Git experience duration. Demonstrate practical knowledge honestly in any assessment.

**Low Priority — specialized domain architecture:** deep financial-ledger design and advanced distributed algorithms are not specified. Prioritize the actual application task, frontend expectations and communication over speculative specialist revision.

## Preparation Plan

**Must prepare:** the Laravel-focused introduction, candid React boundary, current meeting/start availability and English conversation. Decide what further information is needed before identity verification.

**Before technical:** rehearse a compact Laravel/MySQL exercise, refresh frontend fundamentals honestly, review the exact scope of numeric results and establish assessment duration and permitted resources.

**Before final/culture:** select concise independent-delivery and collaboration stories; resolve weekly hours, compensation, communication expectations and contracting details. Do not promise a schedule merely because it appears geographically feasible.
