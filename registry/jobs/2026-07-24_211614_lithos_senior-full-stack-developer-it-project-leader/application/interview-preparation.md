## Technical Interview

High Priority:

- PHP and Laravel architecture: service boundaries, package design, validation, queues, database access, testing, and maintainability.
- REST API design and integrations: authentication, error handling, retries, idempotency, rate limits, data synchronization, and observability.
- Database design with MySQL/PostgreSQL: indexing, query optimization, migrations, transactions, and consistency.
- Technical leadership: estimation, breaking work down, code review, mentoring, release planning, and delivery risk management.
- System integration and automation: connecting business systems, reducing manual work, and maintaining data flow reliability.
- Production reliability: monitoring, logging, fallbacks, incident response, and performance bottleneck analysis.

Medium Priority:

- Scrum and Kanban: practical planning, ceremonies, WIP control, cycle time, delivery metrics, and stakeholder communication.
- Linux-based deployments: service operation, logs, environment configuration, and production troubleshooting.
- CI/CD: GitHub Actions, Helm, ArgoCD, release consistency, rollback thinking.
- Product-data and catalog platforms: prepare to reason from first principles about PIM-like data, versioning, product variants, multilingual catalogs, and sales-network portals.
- HubSpot CRM integrations: not evidenced directly, so prepare integration-design answers using general CRM/API experience without claiming prior HubSpot work.

Low Priority:

- React/Vue implementation details: be ready to explain frontend collaboration and ramp-up plan, but do not present as a specialist.
- Java: acknowledge limited documented evidence and focus on transferable backend design.
- Livewire and FilamentPHP: prepare to discuss Laravel ecosystem ramp-up, but do not claim hands-on experience.
- Nginx specifics: review basic reverse proxy, static assets, PHP-FPM, logs, TLS, and upstream health concepts before interview.

Likely technical questions:

- How would you design a B2B product catalog platform where product data must stay synchronized across site, app, and price lists?
- How would you integrate a CRM such as HubSpot with an internal product or lead workflow?
- How do you prevent stale product information across systems?
- How would you structure Laravel services for a complex business workflow?
- How do you design retry and fallback logic for external integrations?
- How do you monitor deadlines, scope, and technical risks as a project leader?
- How would you mentor junior developers while keeping code quality high?

## CV Deep-Dive Questions

Prepare to defend these claims:

- "Designed and owned a Go-based support automation platform": explain architecture, services connected, ownership boundaries, and operational impact.
- "Automating or deflecting up to 30% of inbound tickets": explain measurement source and what counted as automation/deflection.
- "Played a key role in Agile planning": describe Planning Intervals, roadmap input, task distribution, and team metrics.
- "Increased feature delivery rate by approximately 20%": explain how the metric was tracked and what changed.
- "Led a team of 5 backend engineers": describe team structure, code review, mentoring, and delivery responsibility.
- "Scaled to around 50 million emails per month": explain bottlenecks, queueing, observability, and incident handling.
- "Directly managed 10 developers at Hyprr": explain project context, responsibilities, and how priorities were handled.

Potential weak points to handle:

- React/Vue gap: acknowledge it clearly and pivot to backend leadership, API design, and collaboration with frontend developers.
- Java gap: do not overstate. Say the documented production background is PHP/Go, with transferable backend architecture skills.
- Budgeting gap: distinguish resource planning and delivery tracking from formal budget ownership.
- Timeline conflict between source CV and LinkedIn: use the primary CV chronology consistently unless asked to clarify.
