# Interview Preparation — VMWAY SRL

## Recruiter / HR Screening

The employer advertises Rome hybrid work, one or two client-site days weekly, CCNL Commercio and €25,000–35,000 gross annually. Decide whether these terms work. For a salary expectation, first use the separate compensation benchmark workflow; the posted band is not a candidate commitment.

Prepare to explain the move toward a hands-on PHP role with an honest motivation. The role combines Symfony development, relational data and web services; those are defensible areas to discuss, but do not claim the client or project is known. Explain that CRURATED was a concurrent part-time consulting engagement alongside Simple.life, which ended in October 2026. Confirm the current notice period, earliest start date and willingness to travel to the client site before giving firm answers. Ask which language the team uses and state actual proficiency. Give the real reason for changing work.

## Culture Fit / Behavioral Interview

Prepare STAR stories with actual actions and outcomes, acknowledging shared delivery.

1. **How did you balance security with delivery?** Use the Simple.life outbound telephony project: backend ownership, privacy controls and security review, with frontend and SRE as collaborators. Describe decisions and boundaries rather than implying ownership of their work.
2. **Tell us about integrating different systems.** Use the Go helpdesk gateway and its vendor-neutral model and adapters, with the first B2B demonstration as the documented outcome.
3. **How did you improve a system under load?** Use airSlate's database bottleneck and workload redistribution; explain what evidence was available and avoid claiming unconfirmed cost savings.
4. **When did you simplify a complex process?** Use the shared Snowflake-to-Intercom engine, its interface preservation and the documented removal of repeated full-history reads. Be ready to explain the operational reason for the work.
5. **How have you collaborated on priorities?** Use airSlate delivery planning with product and development; distinguish individual decisions from team alignment.
6. **How did you handle compatibility?** Use CRURATED's parallel publication of event versions; explain the actual consumer migration only to the extent remembered and supported.
7. **How do you help a team deliver?** Use the PDFfiller email service and seasonal peak coordination. Avoid assigning an unverified individual result to the entire team.

## Technical Interview

**High priority — PHP and Symfony:** Review dependency injection, routing, validation, tests and production debugging in Symfony versions actually used. Prepare a concrete example and your contribution. Doctrine is explicitly requested, but it is not confirmed in the current candidate sources; review concepts and state actual experience honestly. Do not imply a prior Doctrine deployment if it cannot be supported.

**High priority — SQL and relational databases:** Rehearse indexes, joins, transactions, query plans and diagnosis of slow queries. Use the airSlate main database example to explain the bottleneck, how the work was coordinated and the observed stability outcome. Distinguish a general MySQL/PostgreSQL background from the specific advanced schema-design experience the advert asks for. Refresh any SQL syntax likely to be used in a short exercise.

**High priority — APIs and integration:** Prepare REST resource design, status codes, validation, idempotency, authentication, timeouts and error handling. The posting allows REST or SOAP; REST is evidenced, whereas SOAP experience is unverified. The CRURATED integration and Simple.life gateway provide real examples, but event-version publication should not be described as a REST API merely because both involve compatibility.

**Medium priority — architecture and system design:** Explain the gateway adapter boundary and how CRURATED event versions reached consumers. Separate retrospective trade-offs from actual decisions; do not claim unmeasured savings.

**Medium priority — coding and delivery:** Practise a small tested PHP service. Review Git collaboration and agile delivery using actual experience, plus airSlate CI/CD and observability. GitHub Actions alone does not establish Git or SVN proficiency.

**Medium priority — infrastructure and frontend context:** Review LAMP/LEMP components and frontend basics honestly; these are unverified. Do not claim the withdrawn airSlate infrastructure migration.

**Low priority — domain-specific detail:** The client and domain are unnamed; ask for context.

Explain Simple.life telephony privacy, security review and responsibilities shared with frontend and SRE. Distinguish CRURATED analytics, event versions and the separate integration, without claiming sole authorship. Explain individual versus team contributions at airSlate, Hyprr and PDFfiller.

**Must prepare:** confirm schedule, language, current availability and practical fit with the posted compensation; identify real Symfony and SQL examples; verify the requested Word/European format. **Before the technical interview:** practise PHP/Symfony, SQL, REST and a concise explanation of the gateway and event compatibility. ## Questions to Ask

1. What does the client product do, and which team owns the backend?
2. Which PHP and Symfony versions are in production, and how is Doctrine used?
3. What are the main SQL and database challenges in the first months?
4. Are integrations primarily REST, SOAP, or both, and where are their contracts maintained?
5. What balance of new development, maintenance and production support is expected?
6. Which days require attendance at the client site, and where is it located?
7. What language does the team use for day-to-day work and technical interviews?
8. Does the requested European Word CV mean a strict Europass template?
9. How are CCNL level and compensation determined for experience beyond the stated range?
