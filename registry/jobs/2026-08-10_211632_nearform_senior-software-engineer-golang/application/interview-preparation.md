## Technical Interview

The posting specifies a one-hour live Go exercise. Practice clarifying requirements, narrating decisions, handling edge cases, adding tests, and finishing a readable solution.

**High Priority**

- **Go:** interfaces, composition, errors, context cancellation, goroutines, channels, synchronization, maps/slices, memory behavior, package design, and idioms.
- **Concurrency / reliability:** bounded worker pools, timeouts, retries, idempotency, backpressure, and graceful shutdown, tied to real message and event pipelines.
- **API / data design:** REST semantics, validation, error models, versioning, observability, schemas, indexes, transactions, query plans, and safe migrations.
- **Testing:** table-driven unit tests, fakes, integration boundaries, deterministic concurrency tests, and the place of end-to-end checks. Use only verified personal examples.
- **Performance:** profiling, latency, throughput, database load, queues, and evidence-led optimization.

**Medium Priority**

- **Cloud / delivery:** AWS, Kubernetes, Helm, GitHub Actions, ArgoCD, rollback, and observability.
- **System design:** a resilient service or event pipeline covering failure modes, consistency, scaling, security, and operations.
- **AI in SDLC:** distinguish building LLM-enabled product workflows from using AI for coding, tests, review, or documentation; ask what Nearform expects.
- **Consulting:** ambiguous requirements, options, trade-offs, documentation, and adaptation to client standards.

**Low Priority**

- **Next.js:** learn request lifecycle, server/client components, API integration, rendering modes, and deployment. Do not claim production experience.
- **Deep frontend design:** likely secondary unless the client expects full-stack work.
