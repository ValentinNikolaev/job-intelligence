## Technical Interview

**High Priority — DDD and architecture:** practice a hypothetical payment domain with aggregates, invariants, domain services, domain events and bounded contexts. Explain consistency and integration boundaries before choosing patterns. Distinguish CQRS from ordinary read/write methods and Event Sourcing from publishing messages. Discuss replay, schema evolution, projections, eventual consistency and operational recovery as design reasoning, not claims of shipped candidate systems.

**High Priority — PHP/Symfony coding:** prepare an API exercise with validation, dependency boundaries, authorization and error handling. Review Doctrine identity maps, unit-of-work behavior and transaction boundaries. The source supports Symfony experience but not deep recent Doctrine ownership; state that limit rather than assigning the listed tools to earlier employers without evidence.

**High Priority — databases:** rehearse PostgreSQL schema choices, indexing, execution-plan interpretation, transaction isolation and query rewriting. Distinguish general optimization experience from an unverified recent PostgreSQL query-plan achievement. Explain how to measure a proposed improvement before claiming a result.

**High Priority — testing:** design integration tests across external providers, asynchronous work and persistence, including dependency setup and repeatability. PHPUnit, Codeception and Behat are study topics until actual usage is substantiated. Discuss testing principles without inventing tool history.

**Medium Priority — infrastructure:** review Kubernetes operations, observability, safe deployment and debugging. Docker internals, Docker Swarm and advanced Jenkins configuration are advertised but unestablished in the evidence. Supported CI/CD experience does not become Jenkins expertise. Ask which tools are mandatory versus illustrative.

**Medium Priority — payments/security domain:** reason through provider timeouts, duplicate callbacks, sensitive logging and auditability. Use Sixt's PCI DSS-related development for its exact scope; do not claim compliance ownership, certification or recent PSP reconciliation delivery.

**Low Priority — frontend implementation:** collaboration is required, but the posting emphasizes backend work. Prioritize clear API contracts over speculative UI-framework preparation.

## Preparation Plan

**Must prepare:** the truthful PHP/event-architecture introduction, clear DDD/tool evidence limits, current location/language/start facts and the security/integration examples.

**Before technical:** rehearse domain modeling, CQRS/Event Sourcing distinctions, a Symfony/Doctrine exercise, PostgreSQL plan analysis and integration-test design. Mark practice separately from experience and review metric context.
