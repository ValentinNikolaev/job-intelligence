## Technical Interview

High Priority: Go service implementation and production diagnosis. Review context cancellation, timeouts, bounded concurrency, error handling and testable external clients. Practise identifying where a slow dependency consumes resources and where retries create additional load. Explain what you would measure before changing concurrency or adding a queue. Tie the discussion to real integration work without asserting that the employer uses the same design.

High Priority: transactional correctness as a learning exercise. Clearly label any order, balance or settlement example hypothetical. Draw explicit states, define which transitions are allowed and decide how a repeated request is detected. Discuss idempotency, atomic updates, auditability and reconciliation after an uncertain external response. Ask a domain specialist to validate the business rules. Technical familiarity with distributed systems does not establish sportsbook-rule expertise.

High Priority: observability and controlled delivery. Explain service-level measurements, structured logs, tracing boundaries and how to separate customer-visible failure from internal retries. Prepare a deployment plan with health checks, rollback criteria and a way to observe the result. Use actual CI/CD experience, while acknowledging any infrastructure operation the candidate has not personally owned.

Medium Priority: database performance and schema design. Work through a query plan, index choice, transaction boundary and contention scenario. Use airSlate's main-database stability result to explain contribution and effect, without turning a peak workload level into a percentage reduction. Medium Priority: event contracts, versioning and downstream backpressure, supported by CRURATED. Medium Priority: supported AWS and Kubernetes concepts after the employer clarifies operational scope. Low Priority: memorising unmentioned vendor tools or offering opinions on betting products as if they were implementation experience.

## Preparation Plan

Must prepare: an honest domain-transition explanation, location/language questions, accurate chronology and a short Go ownership example. Before a technical round: practise one bounded Go exercise, one database diagnosis and one explicitly hypothetical state/reconciliation design. Before a final or culture round: confirm that the domain gap is accepted, establish the backend/DevOps responsibility split, and discuss onboarding support and realistic expectations for learning the product.
