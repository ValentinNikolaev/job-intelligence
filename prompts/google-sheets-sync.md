On this Windows host, use the already provisioned `.codex-work/mongo-venv/Scripts/python.exe` for every `python` command below. Before running, verify Python >=3.11 and imports `yaml`, `pymongo`, and `bson`. On another host use an explicitly provisioned equivalent environment. Missing runtime dependencies are an actionable failure; do not install packages during an unattended run.

1. Run `python run.py storage export-applications --output .codex-work/sheets/export.json`.
2. Read current spreadsheet metadata and bounded CellData for `Отклики` and `История`, including headers, technical fields, and every populated ID row. Save metadata to `.codex-work/sheets/metadata.json`, then run `python run.py sheets read-ranges --metadata .codex-work/sheets/metadata.json --output .codex-work/sheets/ranges.json`. Pass exactly its ranges to the CellData connector and save the structured response as `.codex-work/sheets/cells.json`. These ranges cover the complete current grids from A1; do not shorten them. Run `python run.py sheets observed --metadata .codex-work/sheets/metadata.json --cells .codex-work/sheets/cells.json --ranges .codex-work/sheets/ranges.json --output .codex-work/sheets/observed.json`. This derives IDs and safe append positions deterministically. Preserve manual columns (next action, due date, last contact, contact, notes), unknown tabs/rows, validation, formulas, and formatting. For first setup, verify the pre-migration Drive copy and prove original `Sheet1` empty in a bounded read before generating the setup payload. Never setup again once managed tabs exist.
3. Use `python run.py sheets plan --export .codex-work/sheets/export.json --observed .codex-work/sheets/observed.json --synced-at <fixed-UTC-run-time> --output .codex-work/sheets/plan.json`.
4. Stop without writing if the plan reports duplicate IDs, missing technical headers, invalid revisions, or conflicts. Report the IDs and reasons. Do not overwrite an observed newer revision.
5. A plan containing only no-ops is a successful quiet run: do not mutate cells, timestamps, or formatting. Otherwise generate the exact connector payload with `python run.py sheets requests --plan .codex-work/sheets/plan.json --metadata .codex-work/sheets/metadata.json --observed .codex-work/sheets/observed.json --output .codex-work/sheets/requests.json`, then submit only that payload as one coherent Sheets batch. Address live ID rows only. Send external values as literal cell data, never formulas. Do not alter manual fields.
6. Read back the managed tabs as in step 2, including every changed cell, and convert the new metadata/CellData with `sheets observed` into `.codex-work/sheets/readback.json`. Run `python run.py sheets verify --plan .codex-work/sheets/plan.json --observed .codex-work/sheets/readback.json --output .codex-work/sheets/verify.json`. Treat a failed readback as a failed sync.

Record source/sheet revisions, hashes, counts, conflicts, readback outcome, and Git revision in the run receipt. Notify only on failure, conflict, missing access, or required user action.

Write the receipt atomically to `.codex-work/sheets/receipts/<UTC-run-id>.json`, including the actual source export hash, plan summary, connector read time, verification result (or explicit no-op), completion time, and instruction Git revision. Preserve prior receipts. A no-op receipt must show zero connector writes; it does not require a redundant readback. Never put credentials or temporary signed download links in receipts.

The application sheet has one row per confirmed application. Unknown dates remain blank. `effective_at` and `recorded_at` must remain distinct. A prepared package, CV, or interview state is not proof of an application submission. User-entered statuses are not imported back into the project.
