# Database backup and restore drill

Read `AGENTS.md`, `config/data-services.yaml`, and this file from the current checkout before every run. Invoke the installed `google-drive` and `google-sheets` skills for connector operations. Inspect `git status --short`; stop on real project changes or unresolved merges. Fetch `origin` once and compare the current branch with its configured upstream. Fast-forward a clean behind branch; stop on divergence or missing upstream. Re-read this prompt and config after any update and record the actual Git revision. Do not commit, push, restore production, or change vacancy status.

Use the already provisioned `.codex-work/mongo-venv/Scripts/python.exe` on Windows or `.codex-work/mongo-venv/bin/python` on POSIX. If that path is unavailable, use only an already installed Python 3.11+ interpreter for which `yaml`, `pymongo`, and `bson` import successfully. Record the executable and version. Do not install packages during this unattended run. Use this interpreter for every command below in place of `python`.

Use configured fixed IDs, never names: backup folder `1wsfd-IzS9viLGaU7y3dpQWrGryGyKPTP`, parent `1eNgUTyIqGnDqsakQ3JqwWyQHBjsR_WbK`, and Sheet `1E82sr4Lt-3yEB0Kb_Amso9NCMThcsF0Sy9x7ma5S848`. Do not change sharing or delete earlier successful backups. GitHub Actions must not call Google APIs.

Before creating anything, locate the latest uploaded successful delivery receipt and verify its readback. Use Python `zoneinfo` with `operations.timezone` to compare its successful delivery calendar date with today's calendar date; use `operations.backup_interval_calendar_days` as the allowed interval and do not perform this as model arithmetic. If the latest verifiable success is older than the configured interval, notify that the frequency expired before continuing. A pending upload or failed restore is not a successful backup. Every final delivery receipt records an unambiguous UTC completion timestamp and the corresponding configured-timezone calendar date.

1. Read current spreadsheet metadata and all populated CellData ranges, including manual fields, through the connector. Save a JSON object with `captured_at`, `metadata` and `cells` under `.codex-work/`. Record its own UTC time; do not claim atomicity between Sheets and the database.
2. Run `python run.py storage backup --output .codex-work/backups --sheets-snapshot <snapshot.json>`. The command acquires the shared writer lease, validates artifact references and creates its own deterministic backup ID, parts and manifest. Use the returned directory and ID. If it fails, do not upload. The manifest includes schema, Git revision, UTC timestamps, collection/index inventory, required artifacts, sizes and hashes; secrets and temporary files are excluded.
3. Run `python run.py storage verify-backup --input <returned-directory> --output .codex-work/backup-receipts/<backup_id>-local-verify.json` before delivery. Every receipt path in this procedure must be new; never overwrite an earlier receipt.
4. Before uploading, search the configured folder for the exact `backup_id`. Preserve a locally verified backup directory as pending delivery across connector retries and later runs; reuse its exact ID, parts, and manifest instead of generating a new backup merely to retry upload. Reuse remote files only when every existing object for that exact ID has matching bytes, size, and checksum. Otherwise stop rather than duplicate or replace it.
5. Upload every part under the exact `manifest.parts[].name`; upload the manifest as `<backup_id>-manifest.json`. Read back the remote manifest and download every uploaded file with connector `fetch(download_raw_file=true, include_base64=false)`. Materialize the returned temporary `file_uri.download_url` into a new local directory; keep these temporary signed links out of receipts. Then run `python run.py storage verify-backup --input <downloaded-backup> --output .codex-work/backup-receipts/<backup_id>-download-verify.json`. Verify checksums and sizes against the local manifest. If a connector size limit is encountered, use a deterministic supported split format with a complete manifest; never silently truncate data.
6. Use only `JOBINTEL_TEST_MONGODB_URI` from `sources/.env` or its process-environment override. It must resolve exclusively to loopback hosts; the configured local service is `mongodb://127.0.0.1:27018/?replicaSet=rs0&directConnection=true`. Confirm `hello.setName` is `rs0` and the URI differs from `MONGODB_URI`. Confirm the local replica-set container `jobintel-mongo-test` is running; `docker start jobintel-mongo-test` may restart that existing test container. If Docker or the configured test replica set is unavailable, write a failed receipt and stop.
7. Derive a short unique database name such as `jobintel_restore_<UTC timestamp>_<first 8 backup UUID hex>_<attempt number>`; it must match the isolated prefix rule and remain at most 63 UTF-8 bytes. Use a new empty database and a new artifact directory `.codex-work/restored/<backup_id>/attempt-<NN>` for every attempt. Run `python run.py storage restore --input <downloaded-backup> --database <short-isolated-database> --artifact-output <fresh-artifact-directory> --output .codex-work/backup-receipts/<backup_id>-attempt-<NN>-restore.json`. The restored repository root is `<fresh-artifact-directory>/project`, not the artifact directory itself. Never restore to production and never repoint a source checkout at the drill database.
8. Run `python scripts/verify_restored_backup.py --input <downloaded-backup> --database <short-isolated-database> --artifact-output <fresh-artifact-directory> --output .codex-work/backup-receipts/<backup_id>-attempt-<NN>.json`. This verifier must report `state: success`; exact restored collection/document/index hashes must match the downloaded snapshot; dangling references must be zero; artifact hashes, status history, catalog IDs, and canonical application export must validate. It temporarily routes catalog reads to the isolated test database through process environment only and records `source_files_mutated: false`; it must not edit either checkout. Do not substitute `run.py storage export-applications --database` for this command because that general command uses `MONGODB_URI`.

Mark a backup successful only after the downloaded-copy verification, restore command, and verifier receipt all pass. Preserve all local verification, restore, and verifier receipts, restored artifact directories, and isolated drill databases; do not delete them automatically. Preserve failed restore attempts as diagnostic evidence and never promote them. Assemble a separate final delivery receipt from the immutable manifest, local/download verification receipts, restore receipt, verifier receipt, and connector upload/readback evidence; do not claim the verifier alone contains connector evidence. The verifier supplies the manifest source/database/Sheet summary, exact restore hashes, artifact-reference totals, catalog and application-export hashes, database name, and `source_files_mutated: false`. Upload the final delivery receipt beside the manifest as `receipt-<backup_id>-attempt-<NN>.json` only after success, then read it back and confirm its `receipt_sha256`. A failed attempt keeps `state: failed` locally and, when remote failure evidence is required, uploads it as `failed-receipt-<backup_id>-attempt-<NN>.json`; it never replaces a success receipt. Do not notify on routine success; notify for failure, checksum mismatch, missing connector access, an expired backup frequency, conflict, or required user action.
